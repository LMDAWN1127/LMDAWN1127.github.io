Hands-on with Multi-Stage Dockerfile Builds

Hands-on with Multi-Stage Dockerfile Builds#

Objective

Within a single Dockerfile, use multiple FROM to define multiple build stages; the final image keeps only the artifacts it needs, greatly reducing image size and avoiding shipping the build toolchain into the production image.

root@docker01:/dawn/dockerfile/alpine/MultiStageConstruction# cat Dockerfile
FROM alpine:3.20.2 AS xixi

RUN mkdir /dawn-xixi && \
    dd if=/dev/zero of=/dawn-xixi/bigfile.txt count=024 bs=1M && \
    echo "xixi ~" > /dawn-xixi/xixi.log

FROM alpine:3.20.2 AS haha

RUN mkdir /dawn-haha && \
    dd if=/dev/zero of=/dawn-haha/bigfile.txt count=2048 bs=1M && \
    echo "haha ~ "> /dawn-haha/haha.log

FROM alpine:3.20.2

MAINTAINER dawn

LABEL school=czu \
      class=computer01 \
      offic=www.dawn.com

RUN mkdir /dawn-hehe

# This stage copies data from the other two stages
COPY --from=xixi /dawn-xixi/xixi.log /dawn-hehe
COPY --from=haha /dawn-haha/haha.log /dawn-hehe

ENTRYPOINT ["tail","-f","/etc/hosts"]

The first two stages each generate a large file (24MB and 2048MB bigfile.txt), but the final stage only COPY --froms the two small log files, so the large files never enter the final image.

root@docker01:/dawn/dockerfile/alpine/multiStageGolang# cat Dockerfile
FROM alpine:3.20.2

ADD go1.22.5.linux-amd64.tar.gz /dawn/softwares

RUN ln -svf /dawn/softwares/go/bin/* /usr/local/bin/ && \
    mkdir /dawn/code

COPY hello.go /dawn/code

RUN go build -o /dawn/src/hello /dawn/code/hello.go

FROM alpine:3.20.2

MAINTAINER dawn

LABEL auther=dawn \
      school=czu \
      class=computer01 \
      office=www.dawn.com

COPY --from=0 /dawn/src/hello /

CMD ["tail","-f","/etc/hosts"]
Stage Role Content
First stage（FROM alpine） Build environment Contains the Go SDK; runs go build to produce the binary /dawn/src/hello
Second stage（FROM alpine） Runtime environment Only COPY --from=0 to copy the compiled binary
