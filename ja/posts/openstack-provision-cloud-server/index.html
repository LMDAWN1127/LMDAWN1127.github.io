cloud-init がホスト名やパスワードなどのカスタム情報を初期化します

例えば 20GB のディスクを占有し、快適に動作させるために 4GB のメモリを必要とする大きなイメージを作成したとします。しかしテナントはそれを知らないため、サーバー提供時に 10GB ディスク・2GB メモリのフレーバーを選んで失敗し、原因も分かりません。そこでイメージ登録時に「最小ディスク 20GB・最小メモリ 4GB」を指定しておけば、後にフレーバーを選ぶ際にその条件を満たさないフレーバーは選択できず、条件を満たすものだけを選べるようになります。

以下は OpenStack Nova において新たに追加されたコンピュートノードを所属する Cell データベースに発見・マッピングするために使う重要なコマンドです。Cells v2 アーキテクチャでは、各コンピュートノードはこの登録ステップを経る必要があり、さもないとスケジューラがその上にインスタンスを配置できず、API にもそのホストが表示されません。

1

[root@Controller ~(keystone_admin)]# nova-manage cell_v2 discover_hosts --verbose

実験課題：インターネットにアクセスできるクラウドサーバーを作成し、yum リポジトリを Alibaba Cloud に向け、httpd パッケージをインストールしてサービスを起動し、外部ホストから Web ページ http://192.168.10.182 にアクセスする。

Compute ホストは本質的に KVM ハイパーバイザーです。OpenStack がクラウドサーバーを提供する際、スケジューラがいずれかの Compute ホストに分散配置します。
