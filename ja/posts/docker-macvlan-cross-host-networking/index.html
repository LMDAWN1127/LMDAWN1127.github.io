Docker 実戦：macvlan によるコンテナのクロスホストネットワーク接続#

macvlan は Linux カーネルが提供するネットワーク仮想化技術です。コンテナはホストの物理ネットワーク上で独立した MAC アドレスと IP を直接持ち、物理マシンのようにレイヤ 2 ネットワークに参加できます。本記事では 2 台の Docker ホスト（docker01 / docker02）で macvlan ドライバにより同一セグメントのカスタムネットワークを作成し、コンテナがどのようにクロスホストのレイヤ 2 接続を実現するかを実演します。さらに「macvlan は既定ではホストや外部ネットワークに接続できない」問題の解決策を補足し、最後に WordPress のマルチノードデプロイの実践で締めくくります。

7. macvlan の長所と短所#

長所#

    1. Docker がネイティブに対応しており追加プラグインが不要で、設定も比較的簡単です。
    1. 1〜3 台程度の小規模な Docker 環境に向いています。サーバーが多すぎると IP アドレスの手動割り当てが知らず知らずのうちに作業量を増やします。

短所#

    1. IP アドレスを手動で割り当てる必要があります。自動割り当てにすると複数のホストで自動割り当てされた IP が衝突する可能性があり、その際は人手でのメンテナンスが必要になります;
    1. 同一ホストの同じネットワーク（本例では “dawn_macvlan”）内のコンテナ同士の通信は問題なく、ホストをまたぐコンテナ間通信も問題ありませんが、コンテナは自ホストと通信できず、外部ネットワークにも接続できません;
    1. macvlan は物理 NIC を 1 枚バインドする必要があり、すでにバインド済みの場合は作成できません。

どうしても macvlan を使うなら IP アドレスは手動割り当てになります。ネットワークに出られない問題は “docker network connect” で外部ネットワークに出られる NIC をもう 1 枚割り当てるだけで解決します。
