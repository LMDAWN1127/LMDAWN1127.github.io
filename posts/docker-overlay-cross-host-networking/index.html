Docker 实战：Overlay 实现容器跨主机网络互联与 WordPress 实战

Docker 实战：Overlay 实现容器跨主机网络互联与 WordPress 实战与 WordPress 实战#

1. 实验目标#

  1. 将 docker01 和 docker02 组成一个 Docker Swarm 集群。
  2. 创建自定义 overlay 网络 dawn-overlay，网段为 172.30.0.0/16。
  3. 在 docker02 上启动容器 c1，在 docker01 上启动容器 c2。
  4. 验证两个容器可以跨主机通过 IP 和容器名通信。
  5. 验证容器仍可通过 docker_gwbridge 访问外网。
  6. 在宿主机业务网卡 ens33 上抓取 VXLAN 报文，观察 overlay 的数据封装过程。

2.3 Swarm 所需端口#

端口 协议 用途
2377 TCP Swarm 管理通信，主要用于节点加入和管理节点通信
7946 TCP、UDP 节点之间的发现与状态传播
4789 UDP overlay 网络的 VXLAN 数据封装

如果跨主机 ping 不通，但容器和 overlay 网络均已创建，应优先检查这些端口及中间网络安全策略。

Swarm 模式下的 overlay 网络默认主要供 service/task 使用。如果希望普通容器也能通过 docker run --network dawn-overlay 接入，需要在创建网络时指定 --attachable。

网络刚创建时，在 docker02 上执行：

1
2

docker network ls
docker network inspect dawn-overlay

观察到：

1

Error response from daemon: network dawn-overlay not found

此时 docker network ls 中也只有 bridge、host、none、ingress 和 docker_gwbridge，暂时没有 dawn-overlay。

这不是集群同步失败，而是 Swarm overlay 网络在工作节点上的按需下发机制：网络配置保存在集群中，但工作节点通常在有容器或任务实际需要接入该网络时，才建立本地的数据面资源。

目的地址属于 172.30.0.0/16 时，走 overlay 网卡 eth0。

其他地址走默认路由 172.18.0.1，对应 eth1 和 docker_gwbridge。

11. 实战案例：用 overlay 部署 WordPress#

用自定义 overlay 网络部署 wordpress，网段 172.23.0.0/16。

11.1 创建网络#

1
2
3

# docker01
docker network create -d overlay --attachable \
  --subnet 172.23.0.0/16 --gateway 172.23.0.254 wp-overlay

11.2 在 docker02 部署 MySQL#

1
2
3
4
5
6
7
8

# docker02
docker run -d --name wp-db --network wp-overlay --restart unless-stopped \
  -e MYSQL_DATABASE=wordpress \
  -e MYSQL_USER=wordpress \
  -e MYSQL_PASSWORD=123456 \
  -e MYSQL_ROOT_PASSWORD=123456 \
  -v wp-db-data:/var/lib/mysql \
  mysql:8.4.1-oracle

11.3 在 docker01 部署 WordPress#

1
2
3
4
5
6
7
8

# docker01
docker run -d --name wp-web --network wp-overlay --restart unless-stopped \
  -p 8080:80 \
  -e WORDPRESS_DB_HOST=wp-db:3306 \
  -e WORDPRESS_DB_NAME=wordpress \
  -e WORDPRESS_DB_USER=wordpress \
  -e WORDPRESS_DB_PASSWORD=123456 \
  uhub.service.ucloud.cn/dawn/wordpress:6.8

WORDPRESS_DB_HOST=wp-db:3306 直接使用容器名。两个容器虽在不同宿主机，但同处 wp-overlay 网络，Docker 内置 DNS 会将 wp-db 解析为 docker02 上的 MySQL 容器 IP，实现跨主机数据库访问。

验证跨主机 DNS 解析：

1
2

docker exec wp-web getent hosts wp-db
172.23.0.1  wp-db
