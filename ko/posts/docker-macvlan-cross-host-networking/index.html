Docker 실전: macvlan 으로 구현하는 컨테이너 크로스 호스트 네트워크#

macvlan 은 Linux 커널이 제공하는 네트워크 가상화 기술입니다. 컨테이너는 호스트 물리 네트워크에서 독립된 MAC 주소와 IP 를 직접 가지며 물리 머신처럼 L2 네트워크에 참여합니다. 이 글에서는 두 Docker 호스트(docker01 / docker02)에서 macvlan 드라이버로 같은 대역의 커스텀 네트워크를 만들고 컨테이너가 어떻게 크로스 호스트 L2 통신을 하는지 시연하며, “macvlan 은 기본적으로 호스트나 외부망과 통신할 수 없다"는 문제의 해결책을 덧붙이고 마지막으로 WordPress 멀티 노드 배포 실습으로 마무리합니다.

7. macvlan 의 장단점#

장점#

    1. Docker 가 기본 지원하므로 추가 플러그인이 필요 없고 설정도 비교적 간단하다.
    1. 1~3 대 정도의 소규모 Docker 환경에 적합하다. 서버가 너무 많으면 IP 를 수동 할당하는 작업량이 눈에 띄지 않게 늘어난다.

단점#

    1. IP 주소를 수동으로 할당해야 한다. 자동 할당에 맡기면 여러 호스트에서 자동 할당된 IP 가 충돌할 수 있어 결국 사람이 개입해 관리해야 한다;
    1. 같은 호스트의 같은 네트워크(이 예에서는 “dawn_macvlan”) 안의 컨테이너끼리 통신은 문제없고 호스트를 넘나드는 컨테이너 통신도 문제없지만, 컨테이너는 자기 호스트와 통신할 수 없고 외부망에도 접속할 수 없다;
    1. macvlan 은 물리 NIC 하나를 묶어야 하며 이미 묶여 있으면 생성할 수 없다.

꼭 macvlan 을 써야 한다면 IP 는 수동으로 할당해야 한다. 외부망 접속이 안 되는 문제는 “docker network connect” 로 외부망에 나갈 수 있는 NIC 를 하나 더 붙이면 해결된다.
