K8S Pod 포트 노출과 SVC 멀티포트 매핑 실전: hostPort, 멀티포트 매핑 그리고 targetPort 이름 매칭

이 글은 K8S 에서 Pod 포트 노출과 SVC 멀티포트 매핑 두 가지를 다룬다. 전반부는 hostPort 로 컨테이너 80 포트를 Pod 가 있는 노드의 8888 로 직접 매핑해 SVC 없이 외부에서 컨테이너에 직접 도달한다. Windows 에서 접근 테스트가 성공하고, hostPort 와 NodePort 를 비교한다（hostPort 는 Pod 가 있는 노드에서만 동작하고 Pod 가 옮겨지면 주소도 바뀐다. NodePort 는 모든 노드의 같은 포트를 여는 Service 라서 옮겨져도 영향이 없다）. 후반부는 80/TCP 와 53/UDP 를 동시에 노출하는 Pod 를 쓰고 SVC 로 멀티포트 매핑한 뒤 PORT(S) 열과 describe 의 TargetPort/Endpoints 를 확인한다. 마지막으로 kubectl patch 로 targetPort 를 이름 매칭으로 바꿔, 컨테이너 포트 번호가 바뀌어도 이름만 같으면 SVC 가 계속 추적함을 검증한다.

K8S Pod DNS 정책과 hostNetwork 실전: dnsPolicy 비교 실험

이 글은 대조 실험으로 K8S Pod 의 dnsPolicy 와 hostNetwork 관계를 설명한다. 실험군은 hostNetwork: true 와 함께 dnsPolicy: ClusterFirstWithHostNet 을 명시한다. 컨테이너 안 /etc/resolv.conf 는 클러스터 CoreDNS 를 가리키고 svc 검색 도메인도 있어 db-svc, kubernetes, kube-dns 가 모두 해석된다. 대조군은 hostNetwork 만 켜고 dnsPolicy 는 기본값 ClusterFirst 로 둔다. resolv.conf 가 노드 자신의 DNS 가 되고 검색 도메인도 없어 db-svc 해석이 실패한다. 결론: Pod 가 호스트 네트워크를 쓰면 dnsPolicy 를 반드시 ClusterFirstWithHostNet 으로 바꿔야 한다.
